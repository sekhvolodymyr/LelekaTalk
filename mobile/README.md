# LelekaTalk · Flutter Android

Повністю нативні Flutter-віджети; WebView не використовується. Клієнт звертається до того самого `/api` на `https://lelekatalk.vercel.app`, що й вебверсія. Акаунти, профілі, запрошення, повідомлення, канали, дописи, події та звички спільні. Сервер і схему бази не потрібно змінювати.

## Запуск та APK

Потрібні Flutter **3.47.9**, JDK 17 і Android SDK. З кореня `mobile/`:

```sh
flutter pub get
flutter analyze
flutter test
flutter build apk --release
```

APK: `build/app/outputs/flutter-apk/app-release.apk`. За наявності ігнорованого `android/key.properties` збірка підписується приватним ключем власника. Локальний ключ збережений у `.tools/signing/lelekatalk-release.jks` у корені репозиторію; збережіть резервну копію ключа і `key.properties` для майбутніх оновлень. Без цих файлів CI створює тестовий APK із debug-підписом. Приватні ключі та паролі не комітити.

Локальний API на Android Emulator:

```sh
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3000
```

Для іншого сервера дозволено тільки HTTPS; адреса задається під час збірки. У production APK потрібен інтернет. Локальний HTTP треба окремо дозволити лише в debug manifest при розробці.

## Шифрування та синхронізація

- Вхід тим самим email і паролем; сесійна cookie зберігається через Android Keystore-backed `flutter_secure_storage`.
- Після першого входу на телефоні потрібно ввести **код відновлення з вебверсії**. Ключ не створюється заново, якщо сервер уже має vault. Пароль акаунта не розшифровує історію.
- Нові акаунти отримують сумісні Ed25519/Curve25519 OpenPGP-ключі та код відновлення. Сервер отримує лише public key і зашифрований private key.
- Повідомлення, назви подій і звичок — підписані OpenPGP-конверти з тими самими `kind`, `id`, `senderId` і контекстом, що у вебверсії. Перевіряються підпис, контекст і відбиток ключа; зміна ключа контакту блокує читання/надсилання.
- При роботі клієнта дані оновлюються опитуванням API кожні 2–3 секунди. Тема локальна для пристрою, як локальна тема браузера.
- Вихід відкликає серверну сесію та видаляє локальний матеріал відновлення. Режиму офлайн та черги відкладених повідомлень поки немає.

## Покриття функцій

| Можливість | Нативний клієнт |
|---|---|
| Вхід, реєстрація, два профілі, редагування | Реалізовано |
| Особисті та групові чати, прийняття запрошень, блокування, скарги | Реалізовано |
| Шифрована історія, надсилання, пагінація | Реалізовано; міжмовна сумісність перевіряється тестом |
| Стіна, лайки, коментарі, репости, видалення, поширення | Реалізовано |
| Канали, підписки, стрічка, дописи, коментарі | Реалізовано |
| Календар, редагування, перенесення, ICS, Google-посилання | Реалізовано |
| Звички й відмітки днів | Реалізовано |
| 10 тем вебверсії | Реалізовано з тими самими базовими кольорами |
| Аудіо/відеодзвінки, мікрофон, камера | Реалізовано через flutter_webrtc; потрібна перевірка на двох реальних пристроях |
| Ефіри, перегляд, свайпи, коментарі, лайки | Реалізовано через той самий WebRTC-протокол; потрібна перевірка на пристроях |
| Фонові push та виклики при закритому застосунку | Потребують Android push-провайдера та серверної інтеграції |
| Локальний запис ефіру | Реалізовано: MP4 на пристрої, обмеження приблизно 128 МБ, експорт і видалення; потрібна перевірка на телефоні |
| Англійська локалізація | Системні діалоги підтримують; інтерфейс наразі українською |
| Google OAuth Calendar | Нативний OAuth не підключений; працюють Google-посилання й ICS |
| Платежі, групові дзвінки, ШІ | Не реалізовані й у поточній вебверсії |

Це нативна тестова версія, а не підтверджена повна функціональна або піксельна тотожність вебверсії. Для дзвінків/ефірів зберігаються серверні межі вебверсії: до 5 глядачів, необхідність TURN у частині мереж і відсутність серверного відеоархіву.

## Перевірки

`test/interop_test.dart` запускає ізольований локальний Node-сервер із тимчасовими синтетичними акаунтами. Перевіряє JavaScript → Dart → спільний API → JavaScript, підписи, невірний контекст/автора, відновлення ключа та ключі, створені мобільним клієнтом. Не читає production-дані й `.env`.

`test/api_test.dart` перевіряє сесії, Origin, заборону перенаправлень та незахищених remote URL. `test/calendar_test.dart` — календарні межі, екранування, UTF-8 folding. `test/widget_test.dart` — нативний вхід і список чатів на мобільних розмірах та в усіх темах.
